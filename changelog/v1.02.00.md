# Release Notes - v1.2.0

**Release Date:** November 19, 2025  
**Type:** Minor Release - Feature Enhancement & Refactoring

---

## Overview

Version 1.2.0 focuses on improving email notifications with better context and user experience. The new JobContext class demonstrates SOLID principles by encapsulating job metadata, making the codebase more maintainable and extensible. Users will now see clearer information about whether errors were detected by a scheduled job or manual run, and job links will navigate to the correct Salesforce admin pages.

---

## Added

### Core Features

#### JobContext Class

- **New Inner Class** in `AgentErrorMonitorService`
- Encapsulates job metadata following SOLID Single Responsibility Principle
- Properties:
  - `jobId` - The Salesforce job ID
  - `isScheduledJob` - Boolean flag indicating job type
  - `lookbackHours` - Number of hours to look back for errors
- Benefits:
  - Cleaner code organization
  - Easier to extend with additional metadata
  - Better separation of concerns
  - Type-safe job information passing

#### Enhanced Email Notifications

- **Job Type Differentiation**
  - Emails now distinguish between scheduled and manual job runs
  - Clear indication of execution context
  - Better user understanding of error source

- **Lookback Period Display**
  - Scheduled job emails show the lookback period
  - Format: "Last X hours" in the email subject and body
  - Helps users understand the time window for detected errors

- **Smart Job ID Routing**
  - Job ID links now route to correct Salesforce admin pages
  - Scheduled jobs → `/lightning/setup/ScheduledJobs/page?address=...`
  - Manual/Async jobs → `/lightning/setup/AsyncApexJobs/page?address=...`
  - Improved user navigation experience

### Testing

11. **testJobContextWithNullValues** - Tests JobContext edge cases

## Changed

### Performance Optimization

- **Reduced Query Limit**
  - `MAX_QUERY_RECORDS` reduced from 200 to 100
  - Better performance for large datasets
  - Reduced heap size usage
  - Faster query execution
  - Still handles bulk data efficiently

### Code Refactoring

#### AgentErrorMonitorService

- Refactored email generation to use JobContext
- Improved method signatures with better parameter types
- Enhanced code readability and maintainability
- Better separation of concerns

#### AgentErrorMonitorBatch

- Updated to create and pass JobContext to service
- Enhanced job metadata tracking
- Improved error context in batch processing

#### Test Classes

- **DRY Refactoring**: Introduced helper methods
  - `createTestJobContext()` - Creates test job context
  - `createScheduledJobContext()` - Creates scheduled job context
  - `createManualJobContext()` - Creates manual job context
  - `assertEmailContains()` - Validates email content
- Added 11 new test methods to AgentErrorMonitorServiceTest (20 → 31)
- Reduced code duplication by ~30%
- Improved test readability
- Better test organization

## Removed

### Redundant Code

- **errorCount Field** removed from `ProcessingResult` class
  - Already tracked via `errors.size()`
  - Eliminated redundant data storage
  - Simplified result processing
  - Reduced memory footprint
